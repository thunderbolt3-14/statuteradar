# Phase 6: local review API and CLI

## Scope

Phase 6 exposes the Phase 5 triage contract as a versioned local FastAPI service and command-line runner. The API validates request shapes, calls the same deterministic engine as the CLI, and returns the label, rationale, evidence rule IDs and full reviewed evidence records, scope evidence, conflict pairs, and human-review flag.

Routes:

- `GET /health` — local process health.
- `POST /api/v1/assess` — assess reviewer-supplied structured evidence.
- `/docs` — local OpenAPI interface generated by FastAPI.

The API does not load the corpus, call a model, or infer legal facts. It has no authentication, persistence, or public deployment configuration; keep it bound to localhost. Do not expose it to a network until authentication, authorization, audit retention, and deployment review are added.

## Run locally

With the project dependencies installed in the repository virtual environment:

```bash
venv/Scripts/python.exe scripts/assess_case.py examples/phase5/synthetic_conflict.json
venv/Scripts/python.exe -m uvicorn statuteradar.api:app --app-dir src --host 127.0.0.1 --port 8000
```

Check `http://127.0.0.1:8000/health`, then open `http://127.0.0.1:8000/docs` to submit the synthetic request.

## Phase 6 completion boundary

The local API and CLI are implemented and tested as software interfaces. This is not a production deployment, and Phase 4 annotation, adjudication, the frozen predicate schema, and evaluation remain separate prerequisites for any measured legal-use claim.
